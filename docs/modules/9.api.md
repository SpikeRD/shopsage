# api — FastAPI 路由 / WebSocket 流式 / 限流中间件 / JWT 鉴权

> 🔁 **变更 001 新增了两组路由**（详见 [docs/changes/001](../changes/001-account-login-and-admin-console.md)）：
> 账号接口 `POST /api/auth/login` / `POST /api/auth/refresh` / `GET /api/auth/me`，
> 以及管理接口 `GET|POST /api/admin/accounts`、`PATCH /api/admin/accounts/{id}`、
> `POST /api/admin/accounts/{id}/password`（全部要求 `admin` 权限点）。
> ⚠️ 同时改了鉴权依赖的语义：**每请求查一次账号**（停用/改密/改角色立即生效），
> 且 `thread_id` 形状从 `u{user_id}:` 改为 `c{user_id}:` / `e{emp_id}:`。

## 1. 职责

对外暴露 HTTP / WebSocket 接口：对客（Web/IM）与对内（内部系统）两个入口的请求都从这里进，负责鉴权、限流、参数校验、流式输出，然后转交 `8.graph.md`。

变更 001 起还负责**账号入口**：登录（拿令牌）、刷新（续期）、管理台（开账号/停用/改角色/重置口令）。
但**业务判断不在这一层** —— 认证与账号生命周期全在 `app/security/accounts.py`，
路由只做「异常 → HTTP 错误信封」的映射。

## 2. 对外接口

```http
POST /api/chat                    # 非流式问答
WS   /api/chat/stream             # WebSocket 流式问答（B2）
POST /api/chat/approve            # 人工审批通道
GET  /health                      # 健康检查
GET  /metrics                     # Prometheus 指标（11.observability.md）
```

变更 001 新增（`app/api/auth.py` / `app/api/admin.py`）：

```http
POST   /api/auth/login                                  # 账号 + 口令 → 一对令牌
POST   /api/auth/refresh                                # 刷新令牌 → 新的一对
GET    /api/auth/me                                     # 当前令牌的身份（前端启动自检）
GET    /api/admin/accounts                              # 账号列表（可按 role/status/subject_type 筛）
POST   /api/admin/accounts                              # 建账号（201）
PATCH  /api/admin/accounts/{account_id}                 # 改状态 / 改角色
POST   /api/admin/accounts/{account_id}/password        # 重置口令
```

⚠️ 登录响应的 `entry` 字段是**服务端算好的入口**（`admin` / `internal` / `customer`），
前端不复制这条分流规则。

## 3. 依赖

- `fastapi` + `uvicorn` + `websockets`
- `security/`（JWT 鉴权 `get_current_user`、限流、**账号服务 `accounts.py`**）
- `8.graph.md`（业务入口）、`1.config.md`

## 4. 关键设计决策

1. **对客 / 对内 / 管理走同一 API、靠 JWT 区分角色**：鉴权依赖解析出主体与 `role`，注入到图 state，权限判断集中在 `security/`（不散落在路由）。
2. **WebSocket 做流式**：先出「结论骨架」再补细节，首 token < 1s（B2）。
3. **限流中间件**：按身份 + 接口限流，防滥用与刷接口（D1 纵深）。
   **登录是全项目最严的一条**（10 次/5 分钟）—— 它是唯一能用「猜」换到令牌的入口。
4. **API 层无业务逻辑**：只做「鉴权→校验→转交图→格式化返回」，业务全在 graph/agents，保证可测试、可水平扩容（架构第 8 节无状态化）。
5. **身份依赖会查一次账号**（变更 001）：这是「停用 / 改密 / 改角色立即生效」的落点。
   它同时比对 `token_version` 并把**角色以库为准**。刻意**不做进程内缓存** ——
   缓存会把「立即生效」退回「延迟生效」。代价（鉴权路径不再纯内存）已显式接受。
6. **登录失败不可区分**：账号不存在与口令错误返回同一状态码与同一句文案，
   且未知账号路径也付一次等价耗时的散列验证（防枚举）。

## 5. 核心技术点（要懂为什么）

- **依赖注入（`Depends`）做鉴权**：路由函数声明依赖即可拿到身份，鉴权逻辑一处定义、处处复用。
  ⚠️ 但**「依赖」与「普通函数」不能共用一个默认值**：把 `db: Any = Depends(get_db)` 写进
  `require_principal` 之后，任何直接调用它的地方（`require_actor`、`principal_from_request`、
  `ws_actor`）拿到的会是那个 `Depends` 对象而不是会话 ——
  报 `'Depends' object has no attribute 'execute'`，**且只在真有请求进来时才暴露**。
  处置：`db: Any = None`，缺省时自己开会话并 try/finally 关（见 `deps._session`）。
- **`thread_id` 由服务端从**主体**派生**（变更 001）：`c{user_id}:{session}` / `e{emp_id}:{session}`。
  前缀带主体类别，是为了让「员工 `emp_id=7`」与「客户 `user_id=7`」**不落进同一个会话桶**。
- **流式输出怎么传**：图内 synthesis 逐 token 产出 → 通过 `astream` 事件推送 WebSocket，前端边收边渲染。
- **限流算法**：滑动窗口/令牌桶，Redis 计数，超过阈值返回 429；与 `5.llm.md` 的重试区分——这里拦的是「用户请求」，那里重试的是「模型调用」。
- **无状态可扩容**：会话外置（Redis/Postgres checkpoint），API 多副本无需共享内存（架构第 8 节）。
  ⚠️ 变更 001 后「无状态」有了一个**例外**：鉴权每请求查一次账号（见决策 5）。
- **`require_permission` 取角色的顺序**（变更 001 修过）：**身份对象优先**（`Actor.role`），
  关键字参数 `role=` 最后。反过来的话，一个叫 `role` 的 Query 筛选参数
  （管理台的 `?role=admin`）会被当成**调用者身份** —— 报出「角色 缺少权限：admin」，
  而真正的身份根本没被看一眼。路由还额外写 `identity_from="actor"` 显式绑定。

## 6. 开发步骤

1. 写 `app/api/deps.py`：`get_current_user`（JWT 校验）+ `Actor`（身份 + 会话派生）。
2. 写 `app/api/chat.py`：`POST /api/chat`（转交 `graph.ainvoke`）+ `WS /api/chat/stream`（`astream` 推送）。
3. 写 `app/api/middleware.py`：限流中间件。
4. 写 `app/main.py`：装配 FastAPI app + 中间件 + 路由。
5. 写集成测试（TestClient / websocket 客户端）。
6. **变更 001**：写 `app/api/auth.py`（登录/刷新/me）+ `app/api/admin.py`（账号管理），
   并在 `app/api/account_errors.py` 里把账号领域异常映射成 HTTP 错误信封
   （两个路由模块共用一处映射 —— 抄两份的后果是「同一类错误两种状态码」的漂移）。

**变更 001 新增的用例族** `tests/api/test_auth_accounts.py`（28 条）：

| 分组 | 覆盖的关键性质 |
|---|---|
| 登录 | 正确凭据换到令牌且 `entry` 由服务端算；**四种失败返回同一状态码与同一句文案**（防枚举）；停用账号登不进；请求体塞 `role` → 422 |
| 令牌 | 登录拿到的令牌真能用（`/auth/me` + `/api/chat`）；刷新令牌不能当访问令牌；刷新换到的新令牌能用；拿访问令牌去刷新 → 401 |
| 立即生效 | 停用 / 重置口令 / 改角色后，**该账号在途令牌立刻 401**；停用后**连刷新也 401** |
| 管理授权 | 四个管理接口逐个验（客户令牌 → 404 `not_found_or_forbidden`）；内部员工也进不去（但要能进对内入口） |
| 管理功能 | 开号 201 → 新号立刻能登录；未登记角色 / 不存在主体 → 422；**不能停用自己**；列表不回显凭据字段 |
| 升级 | 变更 001 之前的旧格式令牌被拒 |
