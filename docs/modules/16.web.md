# web — Next.js 前端（对客 / 对内两个入口）

## 1. 职责

提供演示用的两个前端入口：对客（聊天问答）与对内（数据查询/报表），负责调用后端 API、WebSocket 流式渲染、展示溯源与图表。**是演示层，不是核心逻辑**。

## 2. 对外接口

```text
/            # 对客入口（聊天框）
/internal    # 对内入口（员工数据查询/报表）
```

## 3. 依赖

- `next`（App Router）+ TypeScript
- 后端 `9.api.md`（`POST /api/chat` + `WS /api/chat/stream`）
- 图表渲染（接 `6.tools.md` 的 `chart` spec）

## 4. 关键设计决策

1. **两个入口靠角色切换，而非两套前端**：登录后按 JWT 的 `role` 显示对客/对内界面（呼应 `4.security.md` RBAC）。
2. **流式渲染**：WebSocket 逐段接收，打字机效果，首 token 快（B2）。
3. **溯源可视化**：RAG 回答底部展示「来源文档 + 片段」，可点击跳转（`10.rag.md` 溯源）。
4. **前端不做业务判断**：所有权限/越权判断在后端，前端只做展示。

## 5. 核心技术点（要懂为什么）

- **SSR 与流式的关系**：这里流式走 WebSocket 而非 SSE，因为要双向（用户可中断、可追问），且后端已是 WS 流式（`9.api.md`）。
- **图表 spec 解耦**：后端返回结构化 spec，前端用 ECharts/Recharts 渲染，换绘图库不改后端（`6.tools.md`）。

## 6. 开发步骤

1. `npx create-next-app` 初始化 `web/`。
2. 写对客聊天页：接 `WS /api/chat/stream`，流式渲染 + 溯源展示。
3. 写对内页：接 `/api/chat`，展示数据表格 + 图表。
4. 接 JWT 登录，按 role 渲染入口。
5. 写 `web/Dockerfile` + 接入 `2.infra.md` 的 compose。

## 7. 测试用例

```bash
npx next build          # 构建通过
# 手工/组件测试
- 对客页发送问题 → 流式显示回答 + 溯源
- 对内页查询报表 → 表格/图表正常
- 未登录 → 跳登录；低权限员工看不到高敏感字段
```
