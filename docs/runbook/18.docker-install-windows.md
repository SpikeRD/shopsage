## 0. 全景：一共几步、大概多久

```
① 确认 BIOS 虚拟化已开（1 分钟，可能要重启进 BIOS）
        ↓
② 装 WSL2 + Ubuntu（10–20 分钟，含一次重启）
        ↓
③ 装 Docker Desktop（10–15 分钟，含一次注销）
        ↓
④ 配 WSL 内存上限（5 分钟，机器内存只有 5.2GB，这步别跳）
        ↓
⑤ 验证 docker 能跑（2 分钟）
        ↓
⑥ 按 17.docker-ops.md 部署 ShopSage（首次构建 20–60 分钟）
```

**先看这一步**：如果你的目的只是「证明这套编排能跑通」，而手边那台 **VMware-Linux 已经可用**，
那么在那边跑更省事（无需装任何东西、命令与 runbook 完全一致）。
本机装 Docker 更适合「不想依赖另一台机器」「想在 Windows 上直接开发+调试容器」的场景。

## 1. 第一步：确认 BIOS 虚拟化已开启

**这是唯一一个「不满足就彻底装不上」的前提**。WSL2 需要 CPU 的硬件虚拟化（VT-x）。

### 1.1 怎么查（不用重启）

```powershell
# 方法 A：任务管理器 → 性能 → CPU → 看右下角「虚拟化: 已启用」
# 方法 B：命令行（需要管理员 PowerShell）
systeminfo | Select-String "Hyper-V"
```

判据（`systeminfo` 输出里找这四项）：

```
Hyper-V 要求:                    Hyper-V Requirements:
  VM 监视器模式扩展: 是              VM Monitor Mode Extensions: Yes
  固件中已启用虚拟化: 是              Virtualization Enabled In Firmware: Yes    ← 关键
  二级地址转换: 是                   Second Level Address Translation: Yes
  数据执行保护可用: 是                Data Execution Prevention Available: Yes
```

> ⚠️ `固件中已启用虚拟化` 是 **否** → 必须进 BIOS 打开。其它三项是「否」通常不影响 WSL2。

### 1.2 如果显示未启用（Dell G15 5511 的进法）

```text
1. 关机（不是重启，要完全关机）
2. 开机时连按 F2 进 BIOS（Dell 常用 F2；部分机型是 F12 进启动菜单再选 BIOS Setup）
3. 找 Virtualization / VT-x / Intel Virtualization Technology
   （Dell 通常在 "Security" → "Virtualization" 或 "Performance" 分类下）
4. 设为 Enabled
5. 保存退出（F10）
```

> ⚠️ 关掉「快速启动」再进 BIOS 更稳：设置 → 系统 → 电源和睡眠 → 其他电源设置 →
> 选择电源按钮的功能 → 更改当前不可用的设置 → 取消勾选「启用快速启动」。

## 2. 第二步：安装 WSL2 + Ubuntu

本机 `wsl.exe` 存在但**没有任何发行版**（实测 `wsl --list` 输出为空、`--status` 返回 50）。

### 2.1 用一条命令装（推荐）

> ⚠️ **必须以管理员身份**打开 PowerShell。开始菜单搜 `PowerShell` → 右键 → **以管理员身份运行**。

```powershell
wsl --install
```

这条命令会：启用「适用于 Linux 的 Windows 子系统」+「虚拟机平台」两个功能 →
下载并安装 WSL2 内核 → 安装 Ubuntu → **要求重启**。

**重启后**，Ubuntu 会自动启动并要求你设置 **Linux 用户名和密码**（这个密码是 sudo 用的，
与 Windows 密码无关；输入时不显示字符，是正常的）。

### 2.2 如果 `wsl --install` 报错或卡住（分步装）

```powershell
# ① 先只启用功能，不装发行版
wsl --install --no-distribution

# ② 重启电脑（必须）

# ③ 重启后安装 Ubuntu
wsl --install -d Ubuntu

# ④ 把它设为默认版本（WSL2 而不是 WSL1）
wsl --set-default-version 2
```

### 2.3 验证

```powershell
wsl --status
# 期望：默认版本: 2

wsl -l -v
# 期望：
#   NAME      STATE      VERSION
# * Ubuntu    Running    2          ← VERSION 必须是 2，是 1 就用下面的命令转
```

如果 VERSION 是 1：

```powershell
wsl --set-version Ubuntu 2
# 这一步可能要几分钟（要转换文件系统）
```

进 Ubuntu 看看能不能用：

```powershell
wsl -d Ubuntu -- uname -a
# 期望：Linux ... 5.15.x...  x86_64 GNU/Linux
```

> 💡 **可选但强烈建议**：装完更新一次软件源，否则后面 `apt` 装东西会报 404。
>
> ```powershell
> wsl -d Ubuntu -- sudo apt update
> wsl -d Ubuntu -- sudo apt upgrade -y
> ```
>
> 首次 `sudo` 会要你输入 §2.1 设的那个 Linux 密码。

## 3. 第三步：安装 Docker Desktop

### 3.1 下载

官方地址：<https://www.docker.com/products/docker-desktop/>（选 **Windows** 版，
文件名形如 `Docker Desktop Installer.exe`，约 500 MB–1 GB）。

> ⚠️ 只从 `docker.com` 下载。第三方「绿色版/破解版」会把你的镜像源和凭据改到别人服务器上。

### 3.2 安装

1. 双击 `Docker Desktop Installer.exe`；
2. 安装向导里**确认勾选**「Use WSL 2 instead of Hyper-V (recommended)」——
   家庭版只有这一项可选，正常情况下它是唯一出现的选项；
3. 其它保持默认，点 **OK** 开始安装（5–10 分钟）；
4. 安装完点 **Close and restart**（会注销/重启）。

> ⚠️ 如果安装程序报「WSL 2 installation is incomplete」→ 回 §2 检查 WSL 版本是否为 2。
> 如果报「Virtualization support not detected」→ 回 §1，BIOS 虚拟化没开。

### 3.3 首次启动（必须做，否则服务起不来）

重启后从开始菜单启动 **Docker Desktop**：

1. 接受服务条款（Service Agreement）；
2. 如果弹「Sign in」，可以选 **Continue without signing in**（本机开发不需要账号）；
   若要拉取有速率限制的镜像，登录免费账号会好一些；
3. 跳过 survey；
4. 等左下角状态变成 **Engine running**（绿色），大约 30–90 秒。

### 3.4 把当前用户加进 docker-users 组（避免每次 sudo / 权限问题）

```powershell
# 管理员 PowerShell
net localgroup docker-users "$env:USERNAME" /add
```

然后**注销再登录**（或重启）才生效。

### 3.5 验证

```powershell
docker --version
# 期望：Docker version 27.x / 28.x ...

docker compose version
# 期望：Docker Compose version v2.3x.x   ← 必须是 v2（命令是 `docker compose`，中间有空格）

docker run --rm hello-world
# 期望：打印 "Hello from Docker!"，最后一行 "This message shows that your installation appears to be working correctly."
```

> ⚠️ `docker --version` 有输出但 `docker run` 报
> `error during connect: ... The system cannot find the file specified` =
> **Docker Desktop 没启动**（装了 ≠ 在跑）。从开始菜单启动它，等 Engine running。

## 4. 第四步：限制 WSL 内存（★ 本机必做）

**为什么这步不能跳**：本机**当前可用内存只有约 5.2 GB**（`Get-Counter '\Memory\Available MBytes'`
实测；总内存我当时无法读取 —— 沙箱拒绝了 `Win32_ComputerSystem` 查询，你可以在
任务管理器 → 性能 → 内存 里自己确认。按 i7-11800H 的常见配置推测是 16 GB，但**请以实际为准**）。

WSL2 默认会占用**最多 50% 的物理内存**。若总内存是 16 GB，那上限就是 8 GB ——
再加上 Windows 自身占用，在「同时跑 postgres + redis + api + web + prometheus + grafana」时
很容易把机器拖死，症状是整机卡顿、容器被 OOM Kill（`Exit Code 137`）。

### 4.1 写配置文件

在 **Windows 用户目录**建 `.wslconfig`（注意开头的点、**不是**在 WSL 里）：

```powershell
# 在 PowerShell 里执行（不用管理员）
@"
[wsl2]
# 给 WSL 的内存上限：4GB（本栈的合理值；机器富裕可调到 6GB）
# ⚠️ 别超过物理内存的一半，否则 Windows 自己会开始换页，整机变得很卡
memory=4GB

# 交换空间：内存不够时兜底（放在磁盘上，慢但不会 OOM）
swap=2GB

# CPU 核心数：留至少 2 核给 Windows（i7-11800H 是 8 核 16 线程，给 6 核够用）
processors=6

# 关掉 WSL 的「自动回收内存」（旧版本行为不一致，显式关掉更可控）
# 注意：Docker Desktop 4.30+ 自己会管这块，改完下面的命令要重启 WSL
"@ | Set-Content -Path "$env:USERPROFILE\.wslconfig" -Encoding utf8
```

### 4.2 让配置生效

```powershell
wsl --shutdown
# 然后重新打开 Docker Desktop（它会自己把 WSL 拉起来）
```

### 4.3 验证

```powershell
wsl -d Ubuntu -- free -h
# 期望：total 约 4.0Gi（不是 8Gi 以上）
```

> ⚠️ `.wslconfig` 里的 `memory=4GB` 是**给整个 WSL 虚拟机**的上限，
> Docker 的所有容器都共用这 4 GB。所以 §6 里**强烈建议不要开本地 embedding**
> （torch + bge-m3 加载要 2–3 GB，会和其它容器抢内存）。

## 5. 第五步：配置镜像加速（中国大陆网络下强烈建议）

`docker pull` 默认走 Docker Hub，国内经常超时。配一个镜像加速器能省掉大量等待。

**Docker Desktop → 右上角齿轮 Settings → Docker Engine**，把 JSON 改成（在原有内容里
**加上** `"registry-mirrors"` 这一项，不要覆盖掉其它字段）：

```json
{
  "builder": {
    "gc": {
      "defaultKeepStorage": "20GB",
      "enabled": true
    }
  },
  "experimental": false,
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com"
  ]
}
```

点 **Apply & restart**。

> ⚠️ 镜像加速器是**第三方服务**，可用性会变。若 `docker pull` 报
> `Get "https://...": dial tcp: ... timeout`，先把 `registry-mirrors` 清空试一次
> （说明是加速器挂了，不是 Docker 坏了）。
>
> 💡 验证加速是否生效：`docker info | Select-String -Pattern "Registry Mirrors" -Context 0,3`

## 6. 第六步：装完之后的项目侧准备

Docker 装好只是「能跑容器」。要让 **ShopSage** 跑起来，还需要改三处 —— 这三处都是
「本机部署」与「服务器部署」的真实差异，不是可选项。

### 6.1 把项目放到 WSL 文件系统里（强烈建议，性能差别很大）

仓库现在在 `E:\Desktop\DeepSeekHarness\ShopSage`。从 WSL 访问它要走 `/mnt/e/...`，
**跨文件系统**的 I/O 很慢 —— 构建镜像时「transferring context」和 `npm ci` 可能慢好几倍。

两种做法，任选：

```bash
# 做法 A（推荐）：把仓库复制进 WSL 原生文件系统，在那边跑所有 docker 命令
wsl -d Ubuntu -- bash -lc '
  mkdir -p ~ && cd ~ &&
  git clone <你的仓库地址> ShopSage || echo "没有远端的话用下面的做法 B"
'

# 做法 B：不复制，直接在 /mnt/e 下跑（能跑，就是慢）
#   后面所有命令的路径用：
#   cd /mnt/e/Desktop/DeepSeekHarness/ShopSage
```

> ⚠️ **别用 `/mnt/c` 或 `/mnt/e` 放 Docker 的卷数据** —— 卷在 WSL 虚拟机内部，与这个无关；
> 这里说的只是**构建上下文**和 **bind mount 的源码**。
> 本项目的 bind mount 只有 `infra/prometheus/**`、`infra/grafana/**` 等少量配置文件，
> 所以即使留在 `/mnt/e` 也能接受（只是启动稍慢）。

### 6.2 建 `env.list` 并改三处

```bash
cd ~/ShopSage                      # 或 /mnt/e/Desktop/DeepSeekHarness/ShopSage
cp env.list.example env.list
```

在 `env.list` 里改这两项（其余用模板默认值即可）：

| 键 | 模板默认 | 本机要改成 | 为什么 |
|---|---|---|---|
| `API_CORS_ORIGINS` | `https://shopsage.example.com` | `http://localhost:3000,http://127.0.0.1:3000` | 模板是服务器域名；不改则浏览器报 `Failed to fetch`（拿不到 ACAO 头） |
| `EMBEDDING_API_KEY` | **空** | **填阿里云百炼的 key** | ⚠️ 留空会复用 `LLM_API_KEY`（DeepSeek 的），打 dashscope 必然 401 |
| `RAG_RERANK` | `off` | 保持 `off` | `local` 要额外装 torch（+2 GB 镜像） |

> 💡 **好消息（2026-10 变更后）**：`EMBEDDING_BACKEND` 默认已经是 **`litellm`**
> （模型 `dashscope/qwen3.7-text-embedding-flash`），所以**本机不用为内存做任何妥协** ——
> torch 根本不进镜像，4 GB 的 WSL 预算绰绰有余。
>
> 只要填好 `EMBEDDING_API_KEY`，embedding 就能用，且**维度仍是 1024，迁移一行不用改**。

### 6.3 ✅ 向量维度：1024，不用改迁移（这是换模型后的新状态）

`alembic/versions/20261010_..._add_rag_vector_tables.py` 里 `VECTOR_DIM = 1024` 是**写死的**，
而 `EMBEDDING_DIM` / `RAG_VECTOR_DIM` 必须与它一致。

**当前三者都是 1024**（`qwen3.7-text-embedding-flash` 默认输出 1024 维），所以开箱即用：

| 项 | 值 | 需要改吗 |
|---|---|---|
| 迁移里的 `vector(1024)` | 1024 | ❌ 不用 |
| `EMBEDDING_DIM` | 1024 | ❌ 不用 |
| `RAG_VECTOR_DIM` | 1024 | ❌ 不用 |
| `EMBEDDING_BACKEND` | `litellm` | ❌ 不用（已是默认） |
| `EMBEDDING_API_KEY` | 空 | ✅ **必须填** |

> ⚠️ **唯一仍然要注意的**：如果你**曾经用 bge-m3 灌过库**，那些向量与新模型不相容
> （虽然都是 1024 维，但坐标系不同）。必须清空重灌：
>
> ```bash
> docker compose -f docker-compose.yml --project-directory . exec postgres \
>   psql -U shopuser -d shopsage -c "truncate rag_chunks, rag_documents, cache_semantic_entries;"
> docker compose -f docker-compose.yml --project-directory . run --rm api \
>   python -m scripts.load_knowledge_base
> ```
>
> **维度相同 ≠ 向量空间相同** —— 维度守卫（`EMBEDDING_DIM`）拦不住这种错，
> 它只会让检索结果「看起来正常但答非所问」。

> 💡 真想用别的维度（该模型支持 256/512/768/1024）？那就**必须**改迁移里的 `vector(n)`、
> `app/rag/schema.py` 与 `app/cache/schema.py` 的 `VECTOR_DIM`、两处配置，
> 并新增一个 `ALTER COLUMN` 迁移（**不要改历史迁移**）。
> 完整清单见 [`5.llm-runbook.md`](5.llm-runbook.md) §7.6.1。**本机部署不建议动**。

### 6.4 `NEXT_PUBLIC_API_BASE` 用默认值就行（本机特殊情况）

好消息：本机部署时**不用改**它。`docker-compose.yml` 里它的默认插值是
`http://localhost:8000`，而浏览器就跑在这台机器上 —— `localhost` 正好指对。

> ⚠️ 但它是**构建期**变量：如果哪天要改（比如给同事看），必须
> `docker compose ... up -d --build web`，**重启容器无效**（见 `17.docker-ops.md` §5.2）。

### 6.5 确认 `env.list` 是 LF 换行

这个仓库刚加了 `.gitattributes` 把 `env.list` 钉成 LF，但你**手工新建**的文件
编辑器可能仍写成 CRLF。CRLF 的 `env.list` 会让密码值带上一个 `\r`
（`env_file` 解析不剥它）→ 症状是 `password authentication failed` 而两处「看起来一样」。

```bash
# 在 WSL 里查（是 0 就对了）
grep -c $'\r' env.list || echo "无 CR，OK"
```

> 有输出（非 0 或报错）= 含 CRLF，用 `sed -i 's/\r$//' env.list` 修掉。

## 8. 故障速查

| 症状 | 最可能的原因 | 怎么确认 | 修法 |
|---|---|---|---|
| `wsl --install` 报「无法解析服务器名称」 | 网络/DNS 问题（`wsl --install` 要下载发行版） | `ping aka.ms` | 换网络；或用手动方式下载 `.appx`（见 MS 文档） |
| Docker Desktop 启动后一直「Docker Engine starting」 | WSL2 没起来 / 内核太旧 | `wsl -l -v`；`wsl --status` | `wsl --update` 后 `wsl --shutdown`，重启 Docker Desktop |
| `Virtualization support not detected` | BIOS 虚拟化没开 | §1.1 的 `systeminfo` | 进 BIOS 开 VT-x（§1.2） |
| `WSL 2 installation is incomplete` | 只装了 Docker 没装 WSL2 内核 | `wsl --status` | `wsl --update`；仍不行就 `wsl --install --no-distribution` 后重启 |
| `docker run` 报 `error during connect ... cannot find the file` | Docker Desktop 没在跑 | 任务栏有没有小鲸鱼图标 | 启动 Docker Desktop，等 Engine running |
| `permission denied ... //./pipe/docker_engine` | 用户不在 `docker-users` 组 | `net localgroup docker-users` | §3.4 加组，**注销重登** |
| 整机卡死 / 容器 `Exit Code 137` | 内存不足（WSL 抢太多或本栈超限） | `wsl -d Ubuntu -- free -h`；`docker stats` | §4 加 `.wslconfig`；关掉 local embedding（§6.2） |
| `docker pull` 超时 | 国内网络到 Docker Hub | `docker info \| Select-String Mirrors` | §5 配镜像加速 |
| 构建到 `npm ci` / `uv sync` 卡住 | 网络慢 | 构建日志停在哪一步 | 配加速器；重试 |
| 容器起来了但页面 `Failed to fetch` | `API_CORS_ORIGINS` 没含当前 origin | 浏览器 DevTools → Network 看 ACAO 头 | §6.2 改成 `http://localhost:3000,http://127.0.0.1:3000` |
| `password authentication failed` 且两处密码看起来一样 | `env.list` 是 CRLF，密码带了 `\r` | `grep -c $'\r' env.list` | `sed -i 's/\r$//' env.list`（§6.5） |
| `COPY` 报 `not found` / Dockerfile `RUN` 语法怪错 | Dockerfile 被写成 CRLF，`\` 续行失效 | `file app/Dockerfile`（在 WSL 里） | 仓库已加 `.gitattributes`；重新 checkout 一次即可 |

### 8.1 彻底重来（Docker 环境坏了）

```powershell
# ⚠️ 会删除所有镜像、容器、卷 —— 项目数据也会没（如果卷建在这里）
docker system prune -a --volumes

# 更彻底：重置 WSL 里的 Docker 数据
wsl --shutdown
# Docker Desktop → Troubleshoot（虫子图标）→ Clean / Purge data
```

## 9. 关于「本机 vs 服务器」的一个提醒

这套 compose **本来是按 Linux 服务器写的**，在 Windows 上跑有三处不可消除的差异：

| 项 | 服务器 | 本机（Windows + WSL2） |
|---|---|---|
| 文件系统性能 | 原生 ext4 | `/mnt/e` 跨文件系统，**构建慢数倍**（§6.1 建议复制进 WSL） |
| 内存预算 | 通常 8–32 GB | **只有 4 GB 给容器**（§4），embedding 后端要妥协（§6.3） |
| `host.docker.internal` | **不可用**（原生 Engine 解析成 Linux 自己） | ✅ **可用**（Container → WSL → Windows 宿主机） |
| 生产真实性 | 就是生产形态 | 只能验证「编排与配置对不对」，不能当生产环境 |

最后一行最重要：**本机跑通 ≠ 服务器能跑通**。
`17.docker-ops.md` §9 的验收证据要在**目标环境**上取，本机的记录只算「开发环境验证」。

> 💡 顺带修正一处文档遗留：`docs/modules/2.infra.md` §3.1 和几个 runbook 里写着
> 「开发机是 VMware 里的 Windows 客户机」。本机 BIOS 显示是 **Dell G15 5511 实体机**，
> 那句话是早期历史描述。不影响部署（本机装 Docker 反而因为没有嵌套虚拟化而更简单），
> 但读文档时别被它带偏。
