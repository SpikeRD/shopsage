# uv / pytest 基础命令手册

> **定位**：本文是**工具命令速查**（uv 怎么管环境与依赖、pytest 怎么选用例与读输出），不绑定某一步模块。
> 与 `docs/runbook/` 里其余手册的区别：`1.config-guide.md` / `2.infra-runbook.md` / `3.db-runbook.md` 是「第 N 步怎么做」，
> 本文是「任何时候都用得上的底座命令」。
>
> 涉及配置：`pyproject.toml`（`[tool.pytest.ini_options]`、`[dependency-groups]`、`[tool.uv]`）、`tests/conftest.py`。
> 本文命令均已在本机实测，实测环境见 §1.1；带 ⚠️ 的条目是**本机真实踩到的坑**（沙箱权限、退出码语义）。

## 0. 30 秒速查

| 我想… | 命令（**都在仓库根执行**） |
|---|---|
| 建/更新环境与依赖 | `uv sync` |
| CI/复现：lock 过期就失败 | `uv sync --locked` |
| 在项目环境里跑任意命令 | `uv run <cmd>`（如 `uv run python -c "import sys; print(sys.prefix)"`） |
| 跑全部测试 | `uv run pytest -q` |
| 只跑不需要数据库的用例 | `uv run pytest -q -m "not db"` |
| 只跑某个文件 / 某组用例 | `uv run pytest -q tests/test_db_pool.py -k "pool"` |
| 第一条失败就停（先看关键错） | `uv run pytest -q -x` |
| 看用例清单，不执行 | `uv run pytest --collect-only -q` |
| 看某个用例为什么被 skip | `uv run pytest -q -rs` |
| 进 pdb 调试失败点 | `uv run pytest -q --pdb -x` |
| 加依赖（别手写 dependencies） | `uv add <pkg>` / `uv add --dev <pkg>`（dev 用依赖组） |
| 升级锁定版本 | `uv lock --upgrade` 然后 `uv sync` |
| 装完 pytest 后报 `PermissionError` / 缓存写入失败 | §5.1（`UV_CACHE_DIR` / `-p no:cacheprovider`） |
| 「no tests ran」或 `ModuleNotFoundError` | §5.2（**大概率你不在仓库根**，`uv run` 不改工作目录） |

## 1. 环境口径（先对齐版本，再谈命令）

### 1.1 本机实测环境

| 项 | 值 | 怎么确认 |
|---|---|---|
| uv | **0.11.33**（`pyproject.toml` 要求 `>=0.11`） | `uv --version` |
| Python | **3.12.9**（`requires-python = ">=3.12"`） | `uv run python -V` |
| 已装解释器 | 只有 `cpython-3.12.9-windows-x86_64-none` | `uv python list --only-installed` |
| pytest | **9.1.1** | `uv run pytest --version` |
| 虚拟环境 | 仓库根 `.venv`（uv 建、已被 `.gitignore` 忽略） | `uv run python -c "import sys; print(sys.prefix)"` |
| 依赖事实来源 | `uv.lock`（**要提交**；`pip freeze` 那套已弃用） | — |

> 版本口径是**已定的事实**，不要在跑不通时自行降级 Python 或换回 pip：`uv sync` 会按 `uv.lock` 还原出与 CI 一致的环境。

### 1.2 一条铁律：`uv run` 不改工作目录

`uv run` 只保证「**用项目 `.venv` 的解释器**」，**不会**把你的 cwd 挪到仓库根。

所以：

- ✅ 在仓库根执行 `uv run pytest -q` → 正常收集用例；
- ❌ 在 `docs/` 下执行 `uv run pytest -q` → **实测 `exit code 5`、输出只有 1 条 warning（0 用例）**；
  同理 `uv run python -c "import app"` 会 `ModuleNotFoundError: No module named 'app'`（cwd 下没有 `app/`）。

这不是 uv 的 bug：Python 的 `sys.path[0]` / pytest 相对 `testpaths` 都依赖 cwd。**本文与其余手册的命令一律默认你在仓库根。**

## 2. uv 基础

### 2.1 uv 是什么 / 为什么换掉 `python -m venv` + `pip`

uv 是一个用 Rust 写的 Python 包与项目管理器：**建虚拟环境、装依赖、锁版本、跑命令**四件事它都管。本项目**不用** `python -m venv`，理由（本机实测过）：

`python -m venv` 依赖 `ensurepip` 往**临时目录**解压捆绑的 pip wheel，在权限/安全策略受限的机器上会直接失败
（`PermissionError: [Errno 13] ...pip-24.3.1-py3-none-any.whl`），结果 `.venv` 建出来了但**里面没有 pip**。
uv 自己管理解释器与缓存，**不经过 ensurepip**，所以在本机一次跑通；顺带好处是快得多，且 `uv.lock` 消除了「我这能跑、你那不能跑」。

### 2.2 命令总表

| 命令 | 作用 | 什么时候用 |
|---|---|---|
| `uv --version` | 看 uv 版本 | 对不上 `required-version` 时（`>=0.11`） |
| `uv python list --only-installed` | 看本机有哪些解释器 | 排查「找不到 3.12」 |
| `uv python pin 3.12` | 把项目解释器钉在 3.12 | 多版本机器上固定口径 |
| `uv sync` | 建/更新 `.venv` 并装依赖（**默认含 `[dependency-groups] dev`**） | 拿到仓库第一次、改了依赖后 |
| `uv sync --locked` | 同上，但 lock 与 `pyproject.toml` 不一致就**直接失败** | CI、Dockerfile（复现用） |
| `uv sync --no-dev` | 只装运行依赖 | 生产镜像 |
| `uv run <cmd>` | 用项目 `.venv` 跑命令（**免激活**） | 跑 pytest / alembic / python |
| `uv run --no-sync <cmd>` | 跑之前不做依赖同步 | 连续跑很多次命令时省时间 |
| `uv add <pkg>` | 加运行依赖（**同时改 `pyproject.toml` 与 `uv.lock`**） | 加新库 |
| `uv add --dev <pkg>` | 加 dev 依赖（写进依赖组） | 加测试/工具库 |
| `uv remove <pkg>` | 移除依赖 | 删库 |
| `uv lock` / `uv lock --upgrade` | 重算锁文件 / 升级锁定版本 | 想更新依赖版本时（改完记得 `uv sync`） |
| `uv tree` | 打印依赖树 | 查「这包谁带进来的」 |
| `uvx <tool>` | 一次性运行工具，不装进项目 | 临时跑 `ruff`、`httpie` 之类 |

**三条纪律**：

1. **不要手写 `[project] dependencies`**，也不要 `pip install`：用 `uv add`，让它同时维护 `pyproject.toml` 与 `uv.lock`。
2. **`uv.lock` 提交进 Git、且不许手改**：它是解析结果的唯一事实来源。`.venv/` 不提交（已在 `.gitignore`）。
3. **dev 依赖走 `[dependency-groups] dev`（PEP 735）**：`uv sync` 默认就装，**不需要** `--extra dev`。
   （`pyproject.toml` 里那份 `[project.optional-dependencies] dev` 是给不用 uv 的旧 CI 留的 pip 入口，别当真源。）

### 2.3 传统命令 → uv 对照

| 传统方式（已弃用） | 现在用 |
|---|---|
| `python -m venv .venv` | `uv sync`（自动建 `.venv`） |
| `.\.venv\Scripts\Activate.ps1` | **不需要激活**：`uv run <cmd>` |
| `pip install -e ".[dev]"` | `uv sync` |
| `pip install <pkg>` | `uv add <pkg>` |
| `pip install --dev <pkg>` | `uv add --dev <pkg>` |
| `python -m pytest -q` | `uv run pytest -q` |
| `pip freeze > requirements.txt` | `uv.lock`（提交，`uv sync --locked` 复现） |
| `pip install -U <pkg>` | `uv lock --upgrade` + `uv sync` |

## 3. pytest 基础

### 3.1 收集规则（为什么我的函数没被跑到）

pytest 默认只认这些：

| 维度 | 默认规则 |
|---|---|
| 文件 | `test_*.py` 或 `*_test.py` |
| 类 | `Test*`（且**不能有 `__init__`**） |
| 函数 | `test_*` |
| 搜索目录 | 配了 `testpaths` 就只用它 |

本项目的配置（`pyproject.toml`）：

```toml
[tool.pytest.ini_options]
pythonpath = ["."]      # 把仓库根加进 sys.path → 测试里可直接 `from app.config import ...`
testpaths = ["tests"]   # 不传路径时只收集 tests/，不去翻 .venv
```

两点推论：

- 在仓库根跑、且**不传路径**时，`uv run pytest -q` 等价于 `uv run pytest -q tests`；
- `pythonpath = ["."]` 是「免装包也能 import `app`」的关键；**换 cwd 它就不成立了** → 回到 §1.2 的绝对根目录要求。

### 3.2 选用例：路径 / `-k` / `-m`

| 写法 | 含义 |
|---|---|
| `uv run pytest -q` | 全部（`testpaths` 下） |
| `uv run pytest -q tests/test_db_pool.py` | 单个文件 |
| `uv run pytest -q tests/test_db_pool.py::test_pool_size_can_be_overridden_for_tests` | 单个用例（`文件::用例`，类方法再加 `::类::方法`） |
| `uv run pytest -q tests/ -k "pool or session"` | **名字**里含 pool 或 session 的用例（不区分大小写） |
| `uv run pytest -q -m "not db"` | **标记**筛选：只跑没打 `db` 标记的（依赖没起时用这条） |
| `uv run pytest -q -m db` | 只跑需要真库的用例 |
| `uv run pytest -q --lf` | 只跑上次失败的（`--last-failed`） |
| `uv run pytest -q --ff` | 先跑上次失败的，再跑其余 |
| `uv run pytest -q --deselect tests/test_config.py::test_read_dotenv_values_reads_file` | 精确排除一条 |

> `-k` 匹配的是**用例 id 字符串**（文件名 + 类名 + 函数名），`-m` 匹配的是 `@pytest.mark.xxx` 标记 —— 别混。

### 3.3 读输出：常用开关

| 开关 | 作用 |
|---|---|
| `-q` / `-v` / `-vv` | 精简 / 详细 / 更详细（默认 `-v` 会打印每条用例） |
| `-x` / `--maxfail=3` | 第一条失败就停 / 最多失败 N 条后停 |
| `-s` | 不要捕获 stdout（`print` 直接出来；调试时几乎必用） |
| `-rs`（或 `-ra`） | 输出**跳过原因**汇总（`db` 用例为什么 skip 就看这个） |
| `-l` / `--tb=short` / `--tb=long` / `--tb=no` | 失败处打印局部变量 / 缩短 / 加长 / 不打印 traceback |
| `--durations=10` | 最慢的 10 条用例（排查「跑得慢是卡在哪」） |
| `-p no:cacheprovider` | **关掉 `.pytest_cache` 写入**（⚠️ 沙箱下必需，见 §5.1） |
| `--collect-only -q` | 只列用例不执行（确认「有没有被收集到」） |
| `--markers` | 列出本环境所有已注册标记 |
| `--pdb` / `--pdbcls` | 失败时进 pdb（配 `-x` 用） |
| `--setup-show` | 打印 fixture 的 setup/teardown 顺序 |

### 3.4 退出码（脚本/CI 判定的依据）

| 码 | 含义 |
|---|---|
| `0` | 全部通过（**有 skip 也算 0**，skip 不是失败） |
| `1` | 有用例失败 |
| `2` | 执行被打断（Ctrl+C） |
| `3` | **内部错误**（fixture/conftest 崩了，如 `PermissionError` 落在 setup 阶段） |
| `4` | 用法错误（如给 `-m` 传了非法表达式） |
| `5` | **没收集到任何用例** —— 「命令写对了但一个都没跑」的典型信号 |

⚠️ `5` 在本项目最常见的两个成因：**不在仓库根**（§1.2）、`-m "not db"` 与 `-k` 叠加后把用例全过滤掉了。

### 3.5 本项目的标记与 fixture

配置都在 `tests/conftest.py`，只有两件「非通用」的东西，但必须知道：

**① `db` 标记：连不上库自动 skip，不报红**

```python
uv run pytest -q -m db          # 只跑需要真库的
uv run pytest -q -m "not db"    # 依赖没起时只跑纯逻辑
uv run pytest -q -rs            # 看 skip 原因（PostgreSQL 不可达 / 业务表不存在）
```

跳过原因是**可执行的提示**，不是笼统的 skip：

- `PostgreSQL 不可达：检查 .env 的 DATABASE_URL host（本机无 Docker，要填 Linux VM 的 IP）` → 去 `docs/runbook/3.db-runbook.md` §1；
- `业务表不存在：先跑 uv run alembic upgrade head` → 跑迁移。

**② `seeded` 装置：声明即用，数据不够现场补灌（幂等）**

用例里写 `def test_xxx(seeded):` 即可；它会先 `snapshot()` 对账 `MIN_COUNTS`，不达标才 `seed()`。

**③ `_reset_settings_cache`（autouse）：每条用例前后清 `get_settings()` 的 `lru_cache`**

必要性：`get_settings()` 是进程内单例，而 db 模块在 **import 期**就调用它建连接池。清缓存后，
每条用例都从干净单例出发 → **用例与收集顺序无关**（否则会「跑全量绿、单独跑红」这种顺序依赖）。

### 3.6 暂时不跑 / 预期失败

```python
@pytest.mark.skip(reason="等 infra 第 4 步接上 redis 再补")
def test_cache_hit_rate(): ...

@pytest.mark.skipif(sys.version_info < (3, 12), reason="依赖 3.12 语法")
def test_x(): ...

@pytest.mark.xfail(reason="已知未实现，先记录")   # 失败是预期 → 不计入红
def test_y(): ...
```

> 本项目的 skip **不写死在用例上**，而是由 `conftest.pytest_collection_modifyitems` 按「依赖是否可用」动态加，
> 这样同一份代码在「有库 / 无库」两种机器上都是绿的。

## 4. 本项目「uv + pytest」组合命令与实测结果

### 4.1 标准动作

```powershell
# ── 全部在仓库根执行 ──
uv sync                         # 1) 建 .venv + 装依赖（含 dev 组的 pytest）
uv run pytest -q                # 2) 全量（连不上库时 db 用例自动 skip，仍应绿）
uv run pytest -q -m "not db"    # 3) 纯逻辑子集（依赖没起时的日常）
uv run pytest -q tests/test_db_pool.py -k "pool"   # 4) 定点复核
```

### 4.2 本机实测输出（2026-09 复测）

| # | 命令 | 实测结果 | 备注 |
|---|---|---|---|
| 1 | `uv --version` | `uv 0.11.33 (fece32fc5 2026-07-28 x86_64-pc-windows-msvc)` | 与 `required-version = ">=0.11"` 相符 |
| 2 | `uv run pytest --version` | `pytest 9.1.1` | 来自 `.venv`，不是全局 |
| 3 | `uv run pytest --collect-only -q` | **`107 tests collected in 0.99s`** | 收集量随模块推进增长 |
| 4 | `uv run pytest -q -m "not db"` | **`66 passed, 35 deselected, 6 errors in 3.45s`** | 6 errors = §5.1 的沙箱 /tmp 限制，非代码问题 |
| 5 | `uv run pytest -q tests/test_db_pool.py -k pool` | `3 passed in 10.92s` | 定点跑，慢是因为连接池用例要真连库 |
| 6 | 在 `docs/` 下 `uv run pytest -q` | `exit code 5`、0 用例、仅 1 条 warning | **`uv run` 不改工作目录**的铁证（§1.2） |

**正常环境（非受限沙箱）的口径**以模块手册为准：`uv run pytest -q` → **`97 passed, 1 skipped`**（见 `3.db-runbook.md`）。
沙箱里多出的 6 errors 全部来自 `test_config.py` 那 6 条用 `tmp_path` 的用例（环境限制）。

### 4.3 为什么必须用 `uv run pytest`，而不是裸 `pytest`

裸跑（全局解释器上的 `pytest`）在本机会踩两个坑：

1. 全局 pytest 未装 / 版本不同 → 先 `ModuleNotFoundError: No module named 'pytest'`；
2. 即使装了，`sys.path` 里没有仓库根、也拿不到 `.venv` 里的依赖 → `import app` 失败，且限制环境下 `tmp_path` 用例更易报 `PermissionError`。

**结论**：`uv run pytest -q` 才是「接近 CI 真相」的口径。

## 5. 故障速查

### 5.1 缓存 / 临时目录权限类（本机沙箱必读）

| 症状 | 原因 | 处理 |
|---|---|---|
| `uv : error: Failed to initialize cache at C:\Users\...\AppData\Local\uv\cache ... 拒绝访问 (os error 5)` | uv 默认缓存目录在用户目录（`%LOCALAPPDATA%\uv\cache`），被文件沙箱挡在仓库外 | 把缓存指到仓库内：`$env:UV_CACHE_DIR="<仓库根>\.uv-cache"` 后再跑 uv 命令 |
| `PytestCacheWarning: could not create cache path ...\.pytest_cache\v\cache\nodeids` | 同上，pytest 写 `.pytest_cache` 被拒 | 加 `-p no:cacheprovider`（也能顺手规避 `--lf` 失效） |
| 6 条 `test_config.py` 用例 setup 报 `PermissionError` | 用例要用系统临时目录，受限环境不让创建 | **环境限制，不是代码问题**；用 `uv run`（`.venv` 口径）跑即可，或用 `--deselect` 精确排除 |

一条可复制的「沙箱口径」完整命令：

```powershell
$env:UV_CACHE_DIR = "$PWD\.uv-cache"
uv run pytest -q -p no:cacheprovider -m "not db"
# 期望：66 passed, 35 deselected（另可能有 6 条 tmp_path 用例报 PermissionError）
```

### 5.2 用例「没跑到」类

| 症状 | 大概率原因 | 怎么办 |
|---|---|---|
| `no tests ran`，退出码 `5` | **不在仓库根**（`uv run` 不改 cwd） | `cd` 回仓库根再跑；见 §1.2 |
| `ModuleNotFoundError: No module named 'app'` | 同上，或没走 `uv run` | 同上；确认用的是 `uv run python -c ...` |
| 函数写了但没被收集 | 文件名/函数名不符合 `test_*` 规则，或类里有 `__init__` | 改名；用 `--collect-only -q` 确认 |
| `-m "not db"` 之后 0 条 | 表达式把用例全过滤了（`db` 之外没别的可用） | `--collect-only -q -m "not db"` 先看列表 |
| 改了 `testpaths` 但没生效 | pytest 的 `rootdir`/配置来源不是你以为的那个 | 输出头部会打印 `rootdir` 与 `configfile`，照着看 |

### 5.3 依赖 / 环境一致性类

| 症状 | 处理 |
|---|---|
| `uv sync` 报 lock 与 `pyproject.toml` 不一致 | 正常：`uv lock` 重算 lock 并提交；CI 里要的正是「失败」这个行为 |
| 别人机器上能跑、我这里跑不了 | 用 `uv sync --locked` 对齐版本；**不要**手工 `pip install` 打补丁 |
| 想升级 pytest | `uv lock --upgrade`（或 `uv add --dev "pytest>=9"`）后 `uv sync`；改完提交 `uv.lock` |
| `db` 用例全 skip | 按 §3.5 的 skip 原因走：先修 `DATABASE_URL` host，再 `uv run alembic upgrade head` |
