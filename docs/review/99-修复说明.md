# 修复说明（留档）

## 发生了什么

本次整理写入 `docs/review/` 时，部分文件在**写入后被二次转码**，导致中文变成乱码（GBK/UTF-8 双重误解码）。
我做了多轮自动修复，结果**又引入了一次新的误解码**：`02-异常清单.md`、`architecture/diagrams.md`、`consolidated/modules/01-config.md`、`consolidated/modules/03-db.md` 这四个文件的当前内容是**乱码**，无法自动还原（信息已丢失）。

## 受影响文件（4 个，需要重写）

| 文件 | 状态 |
|---|---|
| `docs/review/02-异常清单.md` | ❌ 乱码，需重写 |
| `docs/review/architecture/diagrams.md` | ❌ 乱码，需重写 |
| `docs/review/consolidated/modules/01-config.md` | ❌ 乱码，需重写 |
| `docs/review/consolidated/modules/03-db.md` | ❌ 乱码，需重写 |

## 未受影响

其余全部文件经校验为**正常 UTF-8 中文**：`01-巡视报告.md`、`03-待确认清单.md`、`consolidated/` 其余 26 个文件、`appendix/存疑保留.md`。

## 根因与规避

根因是 PowerShell 在「写文件」与「显示」两侧都做了隐式编码转换（Windows 控制台默认 GBK/936），
`Get-Content`/`Set-Content` 与 `[System.IO.File]::WriteAllText` 混用时会出现「写出是对的、读回是错的」。

**规避办法（后续一律用它）**：只用 write 工具写文件；不要用 shell 读写这些 Markdown；
校验用 read 工具而非 `Get-Content`。
