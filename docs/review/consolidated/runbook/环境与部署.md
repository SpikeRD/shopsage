# 运行手册 · 环境与部署

> 吸收：`docs/runbook/1.config-guide.md`、`2.infra-runbook.md`、`4.uv-pytest-basics.md`、`17.docker-ops.md`、`18.docker-install-windows.md`（合计 1,353 + 316 + 232 + 761 + 328 ≈ 2990 行 → 本文）。

## 目的

从"空机器"到"能打开页面"的全部环境步骤，以及改完代码/配置之后**跑哪一条命令**。

## 关键结论

### A. 运行时与命令底座（uv / pytest）

- 统一用 **uv**：`uv sync` 建 `.venv`，`uv run <cmd>` 免激活。**`uv run` 不改工作目录** —— 命令仍需在仓库根执行（`pyproject.toml:16`）。
- `requires-python = ">=3.12"`，`[tool.uv] required-version = ">=0.11"`。
- pytest：`pythonpath=["."]`、`testpaths=["tests"]`、`asyncio_mode="auto"`，marker `llm_live` / `mcp_live` 默认不开（`pyproject.toml:76-87`）。
- 前端测试不是 pytest：`cd web && npm test`（`node --test tests/*.test.ts`）。

### B. 配置取值顺序（最容易踩）

`进程环境变量 > .env > 代码默认值`；`.env` 是**当前工作目录相对**的。`API_*` 一组由 `app/api/config.py:184 _env_value()` 读（先 `os.environ`）—— 原因见 `consolidated/modules/01-config.md`。

### C. 开发拓扑（跨主机，历史形态）

Windows 开发机跑代码（`uv run`）+ Linux VM 跑依赖容器（`infra/docker-compose.dev.yml`：postgres/redis/prometheus/otel-collector/grafana）。三条硬规则：

1. 端口必须绑 `0.0.0.0`（连接来自另一台机器）；
2. `docker compose -f infra/... --project-directory .` **两个参数缺一不可**（只给 `-f` 会把 `infra/` 当项目目录 → 读不到仓库根 `.env`，变量替换静默退回默认值）；
3. Ubuntu 用 `ufw`，**别碰 firewalld**；先放通 22 再 `ufw enable`。

### D. 部署形态（当前）

| 形态 | 执行位置 | 依据 |
|---|---|---|
| ① 独立 Linux 服务器 | 服务器 `~/ShopSage` | `docs/runbook/17.docker-ops.md` §0.1 |
| ② Windows + Docker Desktop + WSL2 | **WSL Ubuntu 的 `~/shopsage`**（WSL 原生文件系统） | 同上；`docs/runbook/18.docker-install-windows.md` |

形态 ② 必须改的四项（照抄服务器口径会**静默失败**）：

| 项 | 形态 ① | 形态 ② |
|---|---|---|
| `NEXT_PUBLIC_API_BASE` | `http://<服务器IP>:8000` | 用默认 `http://localhost:8000` |
| `API_CORS_ORIGINS` | `https://shopsage.example.com` | `http://localhost:3000,http://127.0.0.1:3000` |
| `EMBEDDING_API_KEY` | 可留空（同厂商） | **必须填**（主模型 DeepSeek、embedding dashscope → 否则首次检索 401） |
| 内存 | 物理内存 | 受 `.wslconfig` 的 `memory=4GB` 约束，否则容器 OOM（`Exit Code 137`） |

### E. 一次部署的命令序列（Linux 侧仓库根）

```bash
cp env.list.example env.list && chmod 600 env.list     # 填真实值
docker compose -f docker-compose.yml --project-directory . config -q   # 只读校验
docker compose -f docker-compose.yml --project-directory . build       # 后端 + web（web 要传 build arg）
docker compose -f docker-compose.yml --project-directory . up -d postgres redis
docker compose -f docker-compose.yml --project-directory . run --rm migrate
docker compose -f docker-compose.yml --project-directory . up -d --wait
uv run python -m scripts.check_infra                    # 配置自检（无 uv 用容器版）
```

### F. 改完之后跑哪条（速查）

| 改了什么 | 命令 | 会不会丢数据 |
|---|---|---|
| `env.list` | `up -d --force-recreate api worker` | 不丢 |
| `app/**` `.py` | `up -d --build api worker`（改模型再补 `run --rm migrate`） | 不丢 |
| `web/**` 或 `NEXT_PUBLIC_API_BASE` | `up -d --build web`（**重启无效**） | 不丢 |
| `pyproject.toml` / `uv.lock` | `up -d --build` | 不丢 |
| `infra/prometheus/**` | `up -d --force-recreate prometheus` | 不丢 |
| 彻底重来 | `down -v && up -d` | ⚠️ **全丢** |

> **两条铁律**（`docs/runbook/17.docker-ops.md:52-59`）：① `docker compose restart` 不重新解析 YAML、不重读 `env.list`；② `env.list` 的改动只对**下一次创建的容器**生效。

### G. Windows 本机装 Docker（一次性的硬件步骤）

BIOS 开虚拟化 → `wsl --install`（装 Ubuntu、设默认 WSL2）→ 装 Docker Desktop → **首次启动必须做完** → 加进 `docker-users` 组 → `.wslconfig` 限制内存（4GB，别超物理内存一半）。
（`docs/runbook/18.docker-install-windows.md` §1–§4）

## 坑（Top 10，按踩到的频率）

| # | 坑 | 一句话修法 |
|---|---|---|
| 1 | 在 `/mnt/e` 下构建（WSL 形态） | 必须用 WSL 原生 `~/shopsage` |
| 2 | `NEXT_PUBLIC_API_BASE` 改了只重启 | 它是**构建期**变量，必须 rebase |
| 3 | `env.list` 改了 `restart` | `up -d --force-recreate` |
| 4 | `POSTGRES_PASSWORD` 改了不生效 | 只在**空数据卷**时生效一次 |
| 5 | `EMBEDDING_BACKEND` 与 `WITH_LOCAL_EMBEDDING` 不一致 | 两者必须一起改，否则首次检索才报错 |
| 6 | 数据库 host 写成 IP | 一律写 compose 服务名 `postgres` / `redis` |
| 7 | 本地 embedding 缓存写仓库外 | `HF_HOME` 指到仓库内 / 容器卷（`app/llm/hf_cache.py` 已自动兜底） |
| 8 | 用 `curl` 做 healthcheck | slim 镜像没有 curl，用 `python -c urllib` |
| 9 | `--workers 4` 随手加 | 默认 1；多副本要先确认限流走 Redis |
| 10 | 脚本输出 `UnicodeEncodeError: gbk` | 设 `PYTHONUTF8=1` |
