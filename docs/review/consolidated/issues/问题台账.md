## 最值钱的三条（建议精读原文）

### 007 · 一条死连接锁死整个事件循环

- **判据**：「等 LLM 回复时退出登录 → 之后一直显示『登录中…』」。
- **根因**：`WebSocketDisconnected`（连接已不可用）与 `WebSocketDisconnect`（收到对端断开消息）**是两个异常**。前者掉进兜底 `except`，而那里对坏内容的处理是"回一条 error 帧 + `continue`"——连接已死时 `receive_*` **不 await 任何 I/O 就立刻抛**，循环里没有任何让出点 → 纯 CPU 忙等占满单线程事件循环。
- **为什么 `asyncio.wait_for` 也压不住**：没有让出点，定时器回调永远没机会跑。

### 009 · "有出处" ≠ "答出来了"

- **判据**：同一句连问两次，第 1 次 `delivered`、第 2 次起 `blocked`，而 `citations` 仍非空。
- **根因**：缓存命中时 `rag_node` 返回 `docs: []`，护栏的"材料摘要"因此恒为 0 条，而答案里全是条款引用 → 判定"编造"在它那边完全正确。
- **教训**：**新增一条"事实不经检索直达"的路径（refund / cache）时，必须同步更新所有核对编造的下游。**

### 010 · 知识库修好了，缓存还在说"没找到"

- **判据**：抽样缓存条目看 `citations=[]` 且答案说"无命中"。
- **根因两层**：① 检索回 0 条的答案被当成正常答案写进缓存；② 灌库**不推进** `corpus_revision`（`IngestReport.doc_changed` 当时根本不存在，传了就 AttributeError）。
- **修法**：灌库推进版本（内容没变则不推进）+ **空结果不进缓存**（产品确认）。
