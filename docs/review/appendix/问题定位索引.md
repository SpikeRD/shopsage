# 附录 · 问题 → 定位速查

> 用途：拿着一个**现象**来找"先看哪个文件、再看哪个 runbook、判据是什么"。
> 与 `../consolidated/runbook/*` 的分工：那边讲"怎么做对"，这边讲"坏了去查哪"。
> 每条都标了代码位置；判据列是区分"正常"与"真坏了"的关键，**不要跳过**。

## A. 起不来 / 连不上

| 现象 | 先看 | 判据 | 详见 |
|---|---|---|---|
| 容器起得来，但业务配置全是默认值 | `env.list` 是否被 `env_file:` 读到（`.env` 只管 `${}` 插值） | `docker compose ... run --rm --no-deps --entrypoint sh api -c 'printenv DATABASE_URL'` | `runbook/环境与部署.md` §D |
| 改了 `env.list` 重启容器无效 | 容器创建时 `os.environ` 就定型了 | 必须 `up -d --force-recreate` | `runbook/环境与部署.md` §F |
| `connection to server at "172.18.x.x" failed` | 连接串 host 写了 IP 而不是服务名 | `getent hosts postgres` 能解析即为正常 | `env.list.example` 注释 |
| 页面能开、WebSocket 一直连不上 | 打开的是不是 `Network:<IP>:3000` | 换 `http://127.0.0.1:3000` 就好了 → 是跨源问题 | `runbook/前端.md` §B |
| `Failed to fetch`（**无状态码**） | 进程起了吗 / CORS 白名单 / 是否漏了方法 | `uv run python -m scripts.check_web_cors` | `runbook/前端.md` §C |
| 后端 `UnicodeEncodeError: gbk` | Windows 控制台编码 | 设 `PYTHONUTF8=1` | `runbook/环境与部署.md` 坑 10 |
| `uv: command not found`（WSL 里） | 容器内替代方案 | 用 `docker compose run api` 里的 `/app/.venv` | `runbook/环境与部署.md` §D |
